3. 功能变更

3.1 消息发送中止 NEW

原版没有中止消息发送的功能，用户发送消息后无法取消。

新版新增完整的 AbortController 支持：

// 全局变量
let _sendAbortController = null;

// 中止函数
function stopSending() {
  if (_sendAbortController) {
    try { _sendAbortController.abort(); } catch(e){}
    _sendAbortController = null;
  }
  if (state.currentStreamMsgId) finalizeAssistantMessage(state.currentStreamMsgId);
  state.isSending = false;
  state.status = { type: 'connected', label: '已连接' };
  bump();
}

// 发送时创建 AbortController
_sendAbortController = new AbortController();
const response = await fetch(url, {
  ...
  signal: _sendAbortController.signal,
});

// 捕获 AbortError
catch (err) {
  if (err.name === 'AbortError') {
    if (state.currentStreamMsgId) finalizeAssistantMessage(state.currentStreamMsgId);
  } else { ... }
}

InputBar 组件在 state.isSending 时显示停止按钮 (方形 SVG)，点击调用 stopSending()。

3.2 会话创建传参修复 FIX

原版的 createSession() 不传递 model/agent/variant 参数，注释写道："opencode serve session creation API does NOT accept model/agent"。

新版根据 API-INTERFACES.md §1.3 文档，在创建会话时正确传递配置参数：

async function createSession() {
  const cfg = state.sessionConfig;
  const body = {};
  // 使用 "id" 字段（非 "modelID"），符合 session 创建 API 规范
  if (cfg.model && cfg.model.id) {
    body.model = { id: cfg.model.id, providerID: cfg.model.providerID };
    if (cfg.variant) body.model.variant = cfg.variant;
  }
  if (cfg.agent) body.agent = cfg.agent;
  const opts = { method: 'POST', body: JSON.stringify(body) };
  ...
}

注意：buildMessageBody() 仍保留 modelID 字段名（与原版一致），作为向后兼容。这样会话创建和消息发送两个路径都能传递模型配置。

3.3 流式渲染性能优化 PERF

原版在 SSE 流式更新时直接操作 DOM innerHTML，每个 delta 都触发完整重渲染。

新版引入 streamBus (EventTarget) 事件总线 + requestAnimationFrame 批处理：

// 1. SSE delta 到达时，不直接操作 DOM，而是标记需要更新
msg.content += text;
if (!msg._raf) {
  msg._raf = requestAnimationFrame(() => {
    msg._raf = null;
    // 2. 通过事件总线通知 MessageItem 组件增量更新
    streamBus.dispatchEvent(new CustomEvent('stream:' + msg.id, {
      detail: { content: msg.content, reasoning: msg.reasoning }
    }));
  });
}

// 3. MessageItem 监听事件，只更新当前消息的 DOM
useEffect(() => {
  function onStream(e) {
    const { content, reasoning, done } = e.detail;
    if (contentRef.current) {
      contentRef.current.innerHTML = renderMarkdown(content);
    }
  }
  streamBus.addEventListener('stream:' + msg.id, onStream);
  return () => streamBus.removeEventListener('stream:' + msg.id, onStream);
}, [msg.isStreaming, msg.id]);

效果：流式渲染时只更新当前消息的 DOM 节点，不触发 Preact 的全量 diff。配合防抖保存 (_saveTimer，500ms 间隔)，大幅减少 localStorage 写入。

3.4 重渲染系统 PERF

原版每次状态变更后手动调用多个渲染函数 (renderSidebar, renderMessages, updateSendBtn 等)。

新版使用 pub/sub 模式的 bump() 函数，所有订阅了 useBump() 的组件自动重渲染：

let _version = 0;
const _listeners = new Set();
function bump() {
  _version++;
  _listeners.forEach(fn => fn(_version));
}
function useBump() {
  const [, setV] = useState(_version);
  useEffect(() => {
    const fn = v => setV(v);
    _listeners.add(fn);
    return () => _listeners.delete(fn);
  }, []);
}

9. 存储架构对齐修复（第二轮）

根据 opencode-storage-architecture.md 文档，修复了以下与后端存储架构不一致的问题：

9.1 消息历史 tool_call/tool_result 丢失 FIX

问题：原 convertServerMsg() 只提取 text 和 reasoning 类型的 part，忽略了 tool_call、tool_use、tool_result 类型。导致加载历史消息时，工具调用记录完全丢失。

修复：重写为 convertServerMsgs()（复数），将单条后端消息拆分为多个前端显示消息：

  • tool_call / tool_use part → 独立的 tool 消息（显示工具名和参数）
  • tool_result part → 追加到最近的 tool 消息内容中
  • text / reasoning part → 合并为一条 assistant/user 消息
  • 新增 content 字段回退：当 parts 中无 text 时，使用后端预拼接的 content 字段

9.2 历史消息顺序错误 FIX

问题：mergeBackendMessages() 使用 [...newOnes, ...session.messages] 将后端历史消息插入到本地消息之前，导致消息顺序颠倒（旧消息显示在新消息上面）。

修复：改为 [...session.messages, ...converted]，后端历史消息追加到末尾，保持时间顺序正确。

9.3 会话删除不调用后端 API FIX

问题：deleteSession() 只在前端和 localStorage 删除会话，不调用 DELETE /api/session/{id}。下次加载时被删除的会话从 SQLite 重新出现。

修复：改为 async function，先调用 DELETE /api/session/{id}（级联删除 message→part），失败时降级为仅本地删除并打印警告。

9.4 会话 directory 字段未持久化 FIX

问题：mergeBackendSessions() 不存储后端返回的 directory 字段，导致切换目录后会话分组失败。saveStorage() 也不保存 directory。

修复：在以下 5 处统一添加 directory 字段：

位置修复内容
createSession()返回的 session 对象增加 directory
mergeBackendSessions()新建和更新会话时存储 directory
ensureSession()从 store 映射时传递 directory
switchDirectory()从 store 映射时传递 directory
saveStorage()localStorage 序列化时保存 directory

9.5 时间戳字段访问修正 FIX

问题：ensureSession() 和 switchDirectory() 在从 store 映射会话时，直接访问 s.time?.created，但 store 中的会话对象用的是 s.createdAt / s.lastActiveAt（前端格式），没有 time 字段。

修复：改为 s.createdAt || s.time?.created 优先使用前端格式字段，回退到后端格式。

10. 已知差异与注意事项

  • 模型选择器参数名差异：createSession() 使用 model.id（符合 API 文档），buildMessageBody() 保留 model.modelID（与原版一致）。两处均传递模型配置，服务端取可用的一方。
  • 默认目录：原版硬编码回退到 C:\Users\xxx\Desktop；新版改为空字符串回退，更通用。如需固定默认目录，可在 initApp() 中修改。
  • 存储键名：原版使用 ocr_v2_{directory} 按目录命名空间存储；新版使用 ocr_state + ocr_msgs_{sessionId} 按会话 ID 存储，更精确。
  • CDN 依赖：新版依赖 esm.sh CDN 加载 Preact 和 htm。离线环境下需替换为本地 vendor 文件。
  • vendor 脚本：marked.min.js 和 purify.min.js 路径不变，仍从 vendor/ 目录加载。
